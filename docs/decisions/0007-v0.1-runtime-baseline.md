# ADR 0007: Version 0.1 Runtime Baseline

- Status: accepted; Admin requirement amended by ADRs 0012 and 0017
- Date: 2026-08-31

## Context

The accepted Apple TV PoC uses ESM-only protocol packages while an ioBroker
adapter is conventionally built as CommonJS. Discovery also depends on an
upstream scan without cancellation. Version 0.1 needs explicit dependency,
module, controller, and process-lifecycle boundaries before those packages
become production dependencies.

## Decision

Build the adapter as CommonJS and load the ESM-only protocol packages through
dynamic imports confined to `src/backends/apple/`. Keep discovery in an owned
child process so timeout and unload can terminate the otherwise non-cancellable
upstream scan.

Version 0.1 requires Node.js 22 or newer and js-controller 7.2.2 or newer. The
current custom-component build requires Admin `>=8.0.0 <9.0.0` as amended by
ADR 0017. Adopt `@basmilius/apple-sdk@0.13.4` and
`@basmilius/apple-common@0.13.4` as exact runtime dependencies. Updates are
deliberate compatibility changes and must not be accepted through a version
range.

The packages remain behind project-owned discovery, pairing, backend, domain,
and projection interfaces. No upstream protocol object or error becomes part of
the public ioBroker state contract. `THIRD_PARTY_NOTICES.md` is included in the
npm artifact and records the reviewed source and license caveat.

Continuous integration first runs package validation, type checking, and linting
on Node.js 22. The adapter-test matrix starts only after that gate passes. It
runs a clean build, unit tests, and the ioBroker integration test on Linux with
Node.js 22, 24, and 26 for routine pushes and pull requests. Semantic-version
tags and manual workflow runs add Windows and macOS for a complete 3 x 3
release/readiness matrix. Fail-fast is disabled for that cross-platform matrix
so every platform reports its result even when another job fails. Tests for
POSIX permission bits run on Linux and macOS; Node.js does not expose equivalent
Windows ACLs through `stat().mode`, so Windows still verifies the portable
persistence, encryption, atomic-write, and cleanup behavior without asserting a
synthetic POSIX mode value.

The integration harness uses the exact stable js-controller version `7.2.2`.
It must not use the moving `dev` tag: the test package reuses a temporary
installation between local runs, and upgrading that installation in place can
execute a new controller against stale test data. Testing a newer controller is
an explicit compatibility change and requires a clean harness plus the supported
Node.js matrix.

## Consequences

ioBroker can continue to launch a conventional adapter entry point while ESM
protocol code is isolated. Discovery has a hard lifecycle boundary. Node.js 20
and older controllers are unsupported. Dependency upgrades require the Node
matrix, unit/package/integration tests, and the real-device acceptance matrix.

## Alternatives Considered

- Convert the complete adapter to ESM: rejected for version 0.1 because it adds
  packaging and controller compatibility risk without improving the protocol
  boundary.
- Run discovery in the adapter process: rejected because the reviewed upstream
  API exposes neither an abort signal nor a reliable timeout.
- Use floating dependency ranges: rejected because reverse-engineered protocol
  behavior may change in otherwise compatible-looking releases.

## Validation

Dynamic loading, isolated discovery, pairing, credential reload, command input,
push events, reconnects, and cleanup passed the recorded PoC on macOS and Linux
ARM64 under Node.js 22 and 24. The adapter unit matrix passes Node.js 22, 24,
and 26; local ioBroker integration start, discovery, and unload pass Node.js 22
and 26. Routine CI covers all three versions on Linux; semantic-version tags and
manual runs cover all three versions on Linux, Windows, and macOS. Both paths
invoke the standard `test:unit` entry point before each integration test.
Compact-mode and the complete Linux aarch64 real-device matrix remain release
gates.
